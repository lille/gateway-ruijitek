# 数据采集云平台 DEMO 架构

## 1. 总体目标

本 DEMO 面向工业现场数据采集、设备接入、状态监测和远程展示场景，重点演示两种接入方案在同一云平台上的统一管理能力。

- 方案 A: 通过硬件网关 DTU 透传接入
- 方案 B: 通过前端网关进行协议采集后上云

平台在云端统一处理设备注册、链路管理、实时数据、历史数据、告警和多端展示。

## 2. 方案 A: DTU 透传

### 2.1 适用场景

- 现场设备协议简单
- 需要快速接入，尽量减少网关侧逻辑
- 希望保持现场侧通信链路尽量轻量

### 2.2 工作方式

DTU 作为透明转发通道，将现场数据原样转发到云端接入服务。

```text
设备/仪表 -> DTU -> 4G/以太网 -> 云端接入网关 -> 消息队列 -> 数据服务 -> 展示端
```

### 2.3 特点

- 现场侧改造小
- 协议兼容由上游设备或云端解析承担
- 适合快速试点和存量设备改造
- 对云端接入服务的协议识别能力要求更高

### 2.4 DEMO 展示点

- DTU 在线状态
- 透传链路质量
- 原始报文接收量
- 云端解析成功率
- 异常链路告警

## 3. 方案 B: 前端网关协议采集

### 3.1 适用场景

- 现场协议多样且复杂
- 需要在边缘侧完成协议规整、点位映射和采样控制
- 需要减少云端解析压力，提升统一性

### 3.2 支持协议

- MODBUS RTU / 485
- MODBUS TCP
- TCP Socket 自定义协议
- PLC 协议采集
- 串口通信协议

### 3.3 工作方式

前端网关直接连接设备，完成协议采集、点位转换、缓存和上报，再通过标准化消息上云。

```text
设备/PLC/仪表 -> 前端网关 -> 点位解析 -> 数据清洗 -> 云端接入网关 -> 数据服务 -> 展示端
```

### 3.4 特点

- 边缘侧完成协议适配，云端数据更统一
- 便于扩展采样频率、补传、缓存和本地规则
- 适合多协议混合场景
- 运维成本低于云端逐个解析原始透传报文

### 3.5 DEMO 展示点

- 协议模板管理
- 点位映射配置
- 采集频率与轮询任务
- 本地缓存与补传队列
- 设备离线和重连状态

## 4. 云平台统一能力

### 4.1 接入层

- 设备注册
- 网关认证
- 链路心跳
- 数据上报
- 协议适配

### 4.2 数据层

- 实时流数据
- 历史时序数据
- 告警事件
- 设备档案
- 点位字典

### 4.3 展示层

- B/S Web 管理端
- Android App
- 微信小程序

## 5. 建议系统结构

```text
[设备层]
DTU / PLC / 仪表 / 串口设备

[边缘层]
DTU 透传网关
前端协议网关

[云接入层]
统一接入服务
MQTT / HTTP / TCP 接入

[平台层]
设备管理
数据存储
规则引擎
告警中心

[展示层]
Web
Android
小程序
```
