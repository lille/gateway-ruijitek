# 现场演示检查表

这份检查表用于正式演示前 10 分钟快速核对。

## 1. 网络检查

- PC、RK3568、平台演示机在同一网段
- PC 能 ping 通 RK3568
- RK3568 能访问平台接收服务 IP
- 网关服务端口未被占用：
  - `8090` Web 配置与 API
  - `15020` DTU 透传接收

## 2. 传感器检查

- ZH-Q006 已供电，电源为 `DC 10V~30V`，推荐 `24V`
- RS485 接线正确：
  - `A -> 485A`
  - `B -> 485B`
  - `GND -> GND`
- 默认通信参数：
  - `9600`
  - `8N1`
  - 无校验
  - 从站地址 `1`

## 3. 第一套方案检查

第一套方案用于演示：`PC 上位机配置 + RK3568/DTU 终端透传 + 平台展示`。

检查项：

- 启动 `rk3568-edge-gateway-demo`
- 确认平台接收服务监听 `15020`
- 打开 `pc-dtu-config-tool`
- 模板选择 `ZH-Q006 空气质量传感器`
- 平台接收服务 IP 填写平台演示机 IP
- 平台接收端口填写 `15020`
- 串口填写 `auto` 或 RK3568 实际串口，例如 `/dev/ttyS4`
- 点击“一键生成 RK3568 配置包”
- RK3568 上运行 `rk3568-dtu-terminal-demo`
- 打开 `web-demo` 页面，确认数据进入平台

预期现象：

- 平台出现 ZH-Q006 设备
- 实时点位包含 `PM2.5 / CO2 / TVOC / 甲醛`
- 历史趋势显示 `PM2.5 / CO2`

## 4. 第二套方案检查

第二套方案用于演示：`RK3568 网关本地 WebServer 配置 + 协议采集 + 平台展示`。

检查项：

- 启动 `rk3568-edge-gateway-demo`
- 浏览器打开 `http://网关IP:8090/`
- 模板选择 `ZH-Q006`
- 协议选择 `MODBUS RTU / RS485`
- 串口填写 `auto` 或 `/dev/ttyS4`
- 波特率为 `9600`
- 从站地址为 `1`
- 起始寄存器为 `0`
- 寄存器数量为 `9`
- 根据现场需要调整告警阈值
- 点击“保存并重载”
- 打开 `web-demo` 页面确认展示

预期现象：

- 网关配置页显示 ZH-Q006 多参数点位
- 平台实时大屏显示：
  - `PM2.5`
  - `CO2`
  - `TVOC`
  - `甲醛`
- 告警阈值调低后，平台出现空气质量告警

## 5. 推荐演示顺序

1. 先演示第二套方案
2. 在 Web 配置页切换 ZH-Q006 模板
3. 调低 PM2.5 或 CO2 阈值触发告警
4. 打开 web-demo 展示实时卡片和历史曲线
5. 再演示第一套方案，说明已有 DTU 场景如何快速接入

## 6. 常见问题

### 页面没有数据

检查：

- `rk3568-edge-gateway-demo` 是否启动
- `web-demo` 的 `/api/*` 是否能访问到网关
- 设备 ID 是否为 `DEV-2001`

### RS485 读不到数据

检查：

- A/B 是否接反
- 串口节点是否正确
- 当前用户是否有串口权限
- 从站地址是否为 `1`
- 波特率是否为 `9600`

### 告警没有触发

检查：

- Web 配置页里的阈值是否保存
- 是否点击了“保存并重载”
- 当前采集值是否超过 warning 或 critical 阈值

## 7. 客户讲解重点

- 第一套方案适合已有 DTU 或透传终端的现场
- 第二套方案适合需要本地配置和边缘自治的现场
- 两套方案都能接入同一个智慧管廊环境监测平台
- ZH-Q006 的核心字段已经按真实 Modbus 寄存器解析
